# Автоматическая приёмка установленного клиента

Отключите оригинальный PlanetVPN. Сохраните работу: проверка создаёт настоящее VPN-соединение и переключает маршрутизацию, поэтому связь с чатом может временно прерваться. Во время теста не меняйте правила через UI и не запускайте другой VPN.

Откройте PowerShell **от администратора** и выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\Projects\SelectiveVpn\scripts\Test-Installed.ps1"
```

Нужен установленный SelectiveVpn и встроенный Windows `curl.exe`; SDK/.NET для самого скрипта не нужен. Скрипт не меняет настройки оригинального клиента и откажется начинать, если обнаружит его активный адаптер. Обычно проверка занимает несколько минут. Каждое подключение ограничено 180 секундами; при необходимости параметр `-ConnectionTimeoutSeconds 300` увеличивает этот предел.

## Что проверяется

1. Запуск службы без VPN: нет активного собственного TUN, доступен прямой HTTPS по домену и числовому IP. Если контрольный адрес Cloudflare недоступен напрямую, тест прерывается как недостоверный, собирает данные и выполняет восстановление.
2. Отдельное приложение `vpn-probe.exe` заблокировано без VPN, а соседнее `direct-probe.exe` достигает того же сервера. Используются копии Windows curl, обычные браузеры не добавляются в тестовые правила.
3. Фиксированная Германия (`pool-54`) + «Авто»: после статуса Connected проверяется настоящий HTTPS из отдельного защищённого процесса; его внешний IP должен отличаться от прямого. Незащищённый процесс должен сохранить прямой внешний IP.
4. Правило домена `cloudflare.com`, затем правило IP `1.1.1.1/32`: запрос должен выйти с того же IP, что и защищённое VPN-приложение. После удаления временных доменных/IP-правил прямой маршрут восстанавливается.
5. Блокировка защищённого приложения после Disconnect и после остановки службы из подключённого состояния. Для каждой блокировки сначала проверяется доступность того же адреса напрямую: один тайм-аут не засчитывается как защита.
6. IPv6-блокировка проверяется дополнительно, если контрольный IPv6 HTTPS-запрос работает без VPN. Иначе записывается SKIP, а не фиктивный PASS.

При повторной приёмке каждый основной маршрут проверяется тремя отдельными запросами; сбой первого не скрывается успехом следующих. Подробный журнал включается автоматически и возвращается к исходной настройке при завершении. Тест также принудительно завершает только установленный `Service\runtime\sing-box.exe`, проверяет блокировку во время обрыва, рост счётчиков ошибок/попыток и успешное автоматическое переподключение с рабочим HTTPS. Отключить этот этап можно параметром `-SkipReconnectTest`. Выбрать другую локацию — `-ServerId pool-56`; фиксированная локация нужна, чтобы смена страны не смешивалась с проверкой правил.

Это HTTPS/TCP-проверки и один реально выбранный в режиме Auto транспорт. Они не доказывают защиту UDP, поведение при перезагрузке/сне или работоспособность каждого протокола. Смена внешнего IP — практический индикатор маршрута; результаты сравниваются с журналами и снимками маршрутов, особенно при меняющемся IP провайдера.

## Настройки и завершение

Перед изменениями сохраняется точная копия `settings.json`. Существующие правила защищённых приложений остаются включены; остальные пользовательские правила временно заменяются тестовыми. После проверки исходные настройки и список защищённых приложений восстанавливаются. **Служба остаётся остановленной**, даже если исходное автоподключение было включено. Сам параметр автоподключения возвращается к прежнему значению только после остановки.

Восстановление вызывается в `finally`, в том числе при ошибке подключения. Отдельный скрытый процесс следит за исчезновением основного PowerShell и пытается восстановить состояние, если окно закрыли. Он не заменяет восстановление после выключения питания/перезагрузки. При ошибке восстановления отчёт явно содержит FAIL; скрипт не выдаёт её за успешную остановку.

Если предыдущий тест прервался и осталась незавершённая папка, новый тест не начнётся. Восстановите её из PowerShell администратора:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\Projects\SelectiveVpn\scripts\Test-Installed.ps1" -Recover -RunDirectory "D:\Projects\SelectiveVpn\artifacts\acceptance\ИМЯ-ПАПКИ"
```

Если пришлось восстанавливать отдельно, для разбора полезна сама папка: `recovery.json` и `test.log` могут быть новее первоначального ZIP. Закрытие окна может оборвать сбор полного отчёта; лучше дождаться строки FINISHED.

## Результаты

Папка и ZIP с датой/временем создаются в `D:\Projects\SelectiveVpn\artifacts\acceptance`. Полный путь печатается в конце. Для разбора пришлите ZIP или путь к нему в этом чате.

- `summary.json`, `checks.json`, `test.log` — итог, этапы и ошибки.
- `*-status.json`, `*-network.json` — состояние клиента, интерфейсы, маршруты и DNS.
- `*.stdout.txt`, `*.stderr.txt` и JSON каждого запроса — ответы curl, коды выхода и внешний IP.
- `service.log`, `engine.log`, `openvpn.log` и предыдущие части этих журналов; связанные события Application.
- `original-settings.json` — резервная копия правил и выбора сервера; `environment.json` — версии/хеши скрипта и сборки.

Отчёт содержит IP-адреса и пути приложений. Профили VPN, ключ API, `engine.json`, `transport.ovpn` и исполняемые файлы в ZIP не включаются. Текущему пользователю разрешено читать отчёт, изменять данные восстановления могут администраторы и SYSTEM.

Коды завершения: `0` — все обязательные проверки прошли, `1` — ошибка или недостоверный результат, `2` — ошибка восстановления. SKIP обозначает непроверенное условие, например недоступный прямой IPv6.

Предварительная проверка без смены сети/состояния службы:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\Projects\SelectiveVpn\scripts\Test-Installed.ps1" -CheckOnly
```

Разработка: `tests/Acceptance/Test-Installed.Tests.ps1 -ScriptPath scripts/Test-Installed.ps1` проверяет обработку реального curl на локальном HTTP-сервере и восстановление на изолированных файлах с подменённым управлением службой. Проверка ACL выполняется при запуске этих тестов администратором. Рабочие WFP-фильтры и маршруты эти локальные тесты не изменяют.
