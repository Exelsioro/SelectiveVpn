# Ручная приёмка исправления SelectiveVpn

Оригинальный VPN можно оставить включённым до начала проверки. Полный тест временно изменит подключение к интернету и может оборвать чат; этот файл доступен локально. Проверяйте по шагам и прекращайте тест на первом неожиданном результате.

## Подготовка и возврат

1. Сохраните открытые документы. Откройте SelectiveVpn из меню «Пуск» и PowerShell.
2. В SelectiveVpn выключите автоподключение, выберите «Остальной трафик: Напрямую», сохраните. Для воспроизводимости временно отключите прежние правила, предварительно записав их состояние.
3. Отключите оригинальный PlanetVPN. Не включайте два клиента одновременно.
4. Если пропадёт обычный интернет: нажмите **«Остановить службу»**, затем включите оригинальный PlanetVPN. Эта кнопка не зависит от RPC подключения. Если UI не отвечает, из PowerShell администратора: `Stop-Service SelectiveVpn`. Не удаляйте чужие маршруты и не сбрасывайте весь сетевой стек.
5. Защищённые приложения при остановленной службе намеренно остаются заблокированными. Для снятия только тестового правила запустите службу, удалите правило `curl.exe`, сохраните. Не используйте глобальное снятие защиты для остальных приложений.

## 1. Отключённый клиент не мешает сети

Служба запущена, VPN отключён, тестовых правил ещё нет. Обычные сайты должны открываться. В PowerShell:

```powershell
& "$env:WINDIR\System32\curl.exe" --noproxy '*' --connect-timeout 5 --max-time 15 https://www.cloudflare.com/cdn-cgi/trace
```

Запишите `ip=` и `loc=` как **DIRECT**. Должен вернуться текст, код завершения `$LASTEXITCODE` — 0. Если прямое подключение к этому адресу у провайдера заблокировано, это отдельно фиксируется; для сравнения потребуется доступный адрес проверки IP.

## 2. Каталог и сохранение выбора

В списке есть «Рекомендуемый», Германия, Нидерланды, Франция и две локации США. Великобритания на момент обновления отвечает API 404 и не добавляется. После «Обновить серверы» состав зависит от ответа сервиса, ранее полученные локации сохраняются при частичной ошибке.

Выберите Германию и OpenVPN TCP, закройте/откройте UI. Выбор должен сохраниться. Нажмите «Остановить службу», затем «Запустить службу»: выбор остаётся, интернет работает, VPN отключён.

## 3. Приложение только через VPN

Добавьте правило **Приложение → Через VPN** для `C:\Windows\System32\curl.exe`, сохраните. Проверьте фактический путь через `Get-Command curl.exe`; для теста используйте именно указанный выше EXE.

Пока VPN отключён, команда из шага 1 должна завершиться ошибкой/тайм-аутом, без ответа сервера. Также проверьте запрос по числовому адресу:

```powershell
& "$env:WINDIR\System32\curl.exe" --noproxy '*' --connect-timeout 5 --max-time 12 https://1.1.1.1/cdn-cgi/trace
```

Обычный браузер, не добавленный в защищённый список, должен продолжать работать.

Выберите **Рекомендуемый + Авто**, нажмите «Подключить». Статус должен показать конкретную локацию и протокол. Повторите команду шага 1: теперь должен быть ответ, `ip=` отличается от DIRECT. Статус «Подключено» без работающего запроса считается провалом теста.

## 4. Отключение, остановка службы и восстановление

Нажмите **«Отключить»**. Запросы curl должны снова блокироваться, браузер должен работать. Подключитесь повторно, затем нажмите **«Остановить службу»** прямо из UI: служба должна остановиться, curl остаться заблокированным, обычная сеть — работать. Запуск службы при выключенном автоподключении не должен сам создавать VPN.

Если отдельное приложение удерживает старый FakeIP в собственном DNS-кэше, перезапустите его и отметьте это в результате. Неработающая сеть во всех приложениях после остановки — ошибка, а не нормальное поведение.

## 5. Домен и IP

Удалите тестовое правило приложения curl, сохраните. Подключите VPN; «Остальной трафик» оставьте «Напрямую».

- Без правил команда шага 1 должна показать DIRECT.
- Добавьте **Домен и поддомены → cloudflare.com → Через VPN**, сохраните и дождитесь переподключения. Команда шага 1 должна показать VPN-IP.
- Отключите это доменное правило, добавьте **IP / CIDR → 1.1.1.1/32 → Через VPN**. Запрос к `https://1.1.1.1/cdn-cgi/trace` должен идти через VPN.
- Удалите тестовые правила, сохраните: прямой маршрут восстанавливается.

Правила приложения имеют приоритет над доменами/IP, поэтому их нельзя оставлять включёнными при проверке доменного/IP-правила. Доменная/IP-маршрутизация работает при подключённом VPN; постоянный запрет вне VPN обеспечивается именно правилами приложений.

## 6. Протоколы и автоматический перебор

Верните curl в список защищённых приложений. На одной локации последовательно выберите VLESS/REALITY, OpenVPN TCP, OpenVPN XOR UDP, OpenVPN XOR TCP. После каждого успешного подключения проверьте HTTPS командой шага 1. Для ручного выбора одного протокола клиент не переключается на другой без вашего выбора.

Обычный OpenVPN UDP тоже проверьте, но доступность зависит от сети/узла: на автоматической проверке он не прошёл TLS-согласование. При отказе должны быть конкретная причина в журнале и работающая обычная сеть после «Отключить».

В режиме **Авто** при неудаче в журнале должна появляться попытка следующего протокола. Если первый вариант сразу работает, это подтверждает подключение, но само по себе не доказывает перебор. «Остановить службу» должна работать и во время неудачной попытки подключения.

## Что сообщить по результатам

Номер первого провалившегося шага; выбранные локация/протокол; текст статуса; код `$LASTEXITCODE`; работал ли браузер после остановки службы. IP достаточно сравнить как «совпал/отличается», публиковать его не требуется.

Кнопка «Открыть журнал» открывает `%ProgramData%\SelectiveVpn\service.log`. Рядом есть `engine.log` и `openvpn.log`. Нужны строки времени сбоя, а не файл с конфигурацией/ключами. Не включайте в сообщение `provider-bootstrap.json`, `engine.json`, `transport.ovpn` и исходные профили.
