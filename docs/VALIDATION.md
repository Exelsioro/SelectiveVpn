# Проверка исправления подключения и управления службой

Дата: 15 ноября 2026. Windows x64, .NET SDK 10.0.401, sing-box 1.14.4, OpenVPN 2.6.12 XOR из локальной установки.

## Подтверждено в этой проверке

- Release-сборка и автономная публикация win-x64 без предупреждений/ошибок. 49 обычных проверок прошли: приоритеты/нормализация правил, конфигурации sing-box, отсутствие TUN в preflight, привязка сокетов к интерфейсам, запрет скриптов/plugin в импортированных OpenVPN-конфигах, HMAC/AES-декодирование API и отказ на повреждённой подписи, сериализация сервера и протокола.
- Реальный API вернул пять локаций: Германия, Нидерланды, Франция, США Нью-Йорк и Портленд. Великобритания (пул 59) ответила HTTP 404. На первой попытке Нидерланды ответили тайм-аутом, при установке — успешно.
- Реальные HTTPS-запросы через локальный SOCKS без общего TUN: VLESS/REALITY, OpenVPN TCP, OpenVPN XOR UDP и OpenVPN XOR TCP — успех. Обычный OpenVPN UDP на проверенном немецком узле: TLS error; это не подтверждённый рабочий транспорт в текущей сети. Последняя проверка выполнена конечными бинарными файлами проекта.
- Установленная Windows-служба стартует в Disconnected без TUN. Выбор Германии/OpenVPN TCP сохраняется после остановки/старта через SCM. При активном оригинальном PlanetVPN попытка подключения завершается явным отказом, статус доступен во время операции. После Disconnect служба повторно останавливается и запускается успешно.
- Системные маршруты по умолчанию до и после проверки установленной службы совпали. Оригинальный PlanetVPN не отключался. Во время транспортных проверок временно создавался только собственный OpenVPN-адаптер; после тестов он закрыт.
- В UI добавлены запуск/остановка службы, обновление каталога, выбор протокола, журнал. Проверка кнопок действительно остановила и запустила службу. Быстрое повторное нажатие выявило гонку ожидания SCM; кнопки теперь взаимно блокируются на время самой операции службы, независимо от RPC подключения. Повторная проверка конечного UI подтвердила завершение обоих обработчиков без зависшей кнопки.

Локальные доказательства (исключены из Git): `private/transport-final.log`, `private/service-check.log`, `private/before-update-routes.json`, `private/after-update-routes.json`, `private/ui-final.log`. Резервная копия прежней программы/данных — `private/backup-before-fix-*`.

## Требуется ручная приёмка

Полное подключение обновлённой службы с общим TUN, маршрутизация реальных приложений/доменов/IP, остановка во время такого соединения и восстановление обычной сети **в этой проверке не выполнены**: пользователь сохраняет оригинальный VPN, чтобы не потерять канал связи. Протокол: [MANUAL-TEST.md](MANUAL-TEST.md). Успешные локальные HTTPS-проверки не подменяют эту приёмку.

Перезагрузка, сон/пробуждение, долгосрочные разрывы и все сочетания сторонних VPN/брандмауэров не проверялись. WFP-компонент не изменён; прежние изолированные WFP/TUN-проверки приведены ниже как история, а не как подтверждение полной исправленной сборки.

# Историческая проверка сборки 0.1.0

Дата: 15 ноября 2026. Среда: Windows x64, .NET SDK 10.0.401, sing-box 1.14.4.

## Выполнено

- Release-сборка службы и WPF без предупреждений и ошибок; автономная публикация win-x64. WPF-окно создано и отрисовано в отдельном smoke-запуске.
- 37 проверок политики и конфигурации: IDN, IPv4/IPv6 CIDR, приоритет приложения, запреты в отключённом состоянии, отказ при неопределённом процессе, проверка реальным движком всех 18 исходных серверных профилей.
- 59 проверок в административном запуске (включая предыдущие): постоянные и загрузочные WFP-фильтры, TCP IPv4/IPv6, отсутствие доставки UDP IPv4/IPv6, допуск только выбранного интерфейса, повторная блокировка, сохранение запрета после аварийного завершения процесса управления, удаление собственных тестовых фильтров.
- Запись и повторное открытие выбранного ID сервера и автоподключения в дисковом хранилище. Запись/чтение профилей через DPAPI; UUID отсутствует в открытом виде в зашифрованном файле.
- Реальный HTTPS-запрос через локальный SOCKS и исходный профиль PlanetVPN node `1001170`: успешный ответ, выход во Франции.
- Реальный TUN с тестовым маршрутом: защищённый EXE выходит во Франции через VLESS; второй EXE по прямому доменному правилу — через основное подключение в Беларуси. В журнале движка подтверждены оба outbound. Приложение блокируется до выдачи допуска и сразу после его отзыва.

Временные WFP-фильтры тестовых приложений удалены после проверки. Никакие серверные UUID, ключи и полный список конфигураций в Git не включены.

## Границы проверки

Полная установка через SCM и работа после перезагрузки Windows требуют отдельной приёмки на целевой системе. Загрузочные фильтры успешно добавлены и удалены через WFP; сама перезагрузка в этой сессии не выполнялась. Не проверялись все 18 серверов живым трафиком, все приложения, взаимодействие со всеми сторонними VPN/антивирусами и долгосрочное восстановление сети после сна.

В обычном режиме тестирования не устанавливается постоянная служба и не заменяется пользовательский маршрут по умолчанию. Для рабочего запуска используйте `scripts/Install.ps1` из README. Результаты тестов не следует трактовать как универсальную гарантию отсутствия любых DNS-метаданных при делегировании запросов системным службам.
