# SelectiveVpn

Независимый VPN-клиент для Windows x64: .NET 10, служба Windows и WPF-интерфейс. Получает конфигурации бесплатных локаций PlanetVPN через API. Поддерживает **VLESS / REALITY**, **OpenVPN UDP/TCP**, **OpenVPN XOR UDP/TCP** и автоматический перебор. Маршрутизацию выполняет sing-box 1.14.4, OpenVPN — проверенный движок из локальной установки PlanetVPN. Оригинальный PlanetVPN.exe для работы не запускается; рекламных компонентов в клиенте нет.

## Возможности

- Маршруты **напрямую / через VPN** для приложений, точных доменов, доменов с поддоменами и IPv4/IPv6-подсетей.
- Выбор локации из обновляемого каталога или «Рекомендуемый» (доступность TCP, последний успешный сервер, задержка; затем обязательная HTTPS-проверка). Протокол выбирается отдельно; «Авто» пробует поддерживаемые протоколы по очереди. **Выбор сохраняется сразу**, независимо от сохранения правил, и восстанавливается после перезапуска. При подключённом VPN смена сервера переподключает туннель.
- Приложения с правилом «через VPN» получают постоянный запрет WFP. После проверки VPN разрешается только сетевой интерфейс туннеля. При отключении, падении службы или движка прямое подключение этих приложений остаётся закрытым.
- Автоподключение при запуске службы, проверка доступности через VPN и повторное подключение после сбоя.
- Каталог PlanetVPN и импорт Xray JSON, OpenVPN `.ovpn` и WireGuard `.conf`. Профили можно проверять и удалять во вкладке «Серверы». Ключи и данные авторизации сохраняются через Windows DPAPI.

## Быстрый запуск

Проект: `D:\Projects\SelectiveVpn`. Готовая автономная сборка находится в `artifacts\publish`; установленный .NET для её запуска не требуется.

1. Отключите оригинальный PlanetVPN и другие полнотуннельные VPN перед первым обычным запуском нового клиента.
2. Откройте PowerShell **от администратора**:

```powershell
Set-Location D:\Projects\SelectiveVpn
.\scripts\Install.ps1
```

3. Откройте **SelectiveVpn** в меню «Пуск». Интерфейс запросит повышение прав для управления системной политикой.
4. Выберите сервер. Выбор сохраняется автоматически. Добавьте приложения/домены/IP и нажмите **«Сохранить изменения»**.
5. Нажмите **«Подключить»**. При необходимости включите «Подключать при запуске службы» и сохраните правила.

Если PowerShell блокирует запуск локального скрипта, его можно вызвать без изменения постоянной политики:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Install.ps1
```

В `private/provider-bootstrap.json` хранится локальный ключ декодирования формата API, извлечённый из исходного клиента. Установщик переносит его в DPAPI-хранилище и обновляет каталог. Исходные 18 французских профилей остаются резервным локальным импортом. Запрашиваются бесплатные пулы Германии, Нидерландов, Франции, Великобритании и двух городов США; недоступный пул не выдаётся за работающий. При частичном обновлении ранее полученные другие локации сохраняются.

Выбранные сервер и протокол сохраняются сразу. В режиме «Авто» сначала проверяется последний успешный вариант, затем остальные доступные варианты. Перед созданием общего TUN выполняется HTTPS-проверка через отдельный локальный SOCKS; после создания TUN проверка повторяется. При работающем оригинальном PlanetVPN подключение отклоняется с понятной причиной, без изменения его настроек.

Автоматическая приёмка с журналами и остановкой службы: [docs/AUTOMATED-TEST.md](docs/AUTOMATED-TEST.md).

Пошаговая ручная приёмка после обновления: [docs/MANUAL-TEST.md](docs/MANUAL-TEST.md).

## Как применяются правила

| Приоритет | Тип | Пример |
|---|---|---|
| 1 | Приложение через VPN | `C:\Apps\Browser\browser.exe` |
| 2 | Приложение напрямую | `C:\Apps\Game\game.exe` |
| 3 | Точный домен / домен с поддоменами | `example.com`, `*.example.com` |
| 4 | IP / CIDR | `203.0.113.7`, `203.0.113.0/24`, `2001:db8::/32` |
| 5 | Остальной трафик | По умолчанию — напрямую |

Внутри одной группы действует первое совпадение; кнопки ↑ и ↓ меняют порядок. Правило приложения «через VPN» нельзя ослабить доменным правилом «напрямую». Для помощников браузера/лаунчера, которые сами создают соединения, нужны отдельные пути к их `.exe`.

«Отключить» останавливает туннель VPN и очищает системный DNS-кэш. По умолчанию TUN при отключении убирается. Постоянные блокировки защищённых приложений остаются.

Чтобы блокировать распознанные VPN-домены при отключённом туннеле, включите «Блокировать VPN-домены без подключения» и нажмите «Сохранить изменения». При наличии включённых VPN-доменов служба оставляет локальный TUN для фильтрации. Явные правила сохраняют свой приоритет. Для трафика вне правил при отключении действует прямой маршрут. Строка состояния показывает, запущен ли фильтр.

Фильтрация доменов зависит от распознавания имени по DNS и трафику. Она прерывается при остановке службы, при падении движка до его перезапуска и на время замены сетевого движка при переподключении. Для постоянной защиты конкретной программы задайте правило «Приложение → Через VPN». Кнопка «Остановить службу» управляет Windows SCM независимо от канала подключения; «Запустить службу» запускает её обратно. Закрытие окна не останавливает службу.

При наличии защищённых приложений трафик, для которого движок не смог определить процесс, направляется только через VPN. Это предотвращает прямую утечку и сброс из-за отсутствующего имени процесса, но такой поток может уйти через VPN вместо ожидаемого прямого маршрута. Подробный журнал позволяет выявить эти случаи. Это может потребовать разбора совместимости отдельных приложений, но не даёт ему незаметно уйти по маршруту по умолчанию.

## Защита и её границы

WFP-фильтры привязаны к пути исполняемого файла и покрывают IPv4/IPv6, исходящие подключения и входящие потоки. Постоянные и загрузочные запреты отделены от временного разрешения TUN. Разрешение живёт в динамической WFP-сессии службы и исчезает при её аварийном завершении. Движок привязан к Windows Job Object; служба проверяет его SHA256 перед запуском.

Настройки находятся в `%ProgramData%\SelectiveVpn`, программа — в `%ProgramFiles%\SelectiveVpn`. Доступ к каталогу данных и каналу управления имеют SYSTEM и администраторы. Интерфейс проверяет образ процесса, которому принадлежит канал. Во время работы движок получает JSON с ключами в защищённом каталоге; после штатной остановки этот временный файл удаляется. DPAPI здесь защищает данные на диске, но не скрывает их от администратора компьютера.

Доменные правила опираются на DNS/FakeIP и определение имени соединения. Собственный DoH приложения, ECH, соединения по IP и сторонние локальные прокси могут мешать определению домена. Для строгого ограничения приложения используйте именно правило по `.exe`. Это не песочница для враждебных процессов: обращения через сторонние помощники или системные службы учитываются как трафик этих помощников/служб.

Гарантия запрета вне VPN относится к приложениям, явно отмеченным «через VPN». Доменная/IP-маршрутизация и маршрут «остальной трафик» требуют работающего движка; они не заменяют глобальный системный kill switch при полной остановке службы. После полной остановки службы программы с собственным DNS-кэшем FakeIP иногда нужно перезапустить. При повторном подключении сохранённые DNS-сопоставления снова доступны; между подключениями локальный движок не работает.

## Сборка и проверки

Для сборки нужен .NET SDK 10.0.401 (Windows x64). Скрипт скачивает закреплённый sing-box и проверяет SHA256 архива и EXE. OpenVPN и его DLL берутся из `D:\PlanetVPN\bin\openvpn`, сверяются с `scripts/openvpn-manifest.json`; другой исходный каталог можно передать в `Get-OpenVpn.ps1 -Source`. WireGuard и IKEv2 в этой версии не реализованы.

```powershell
.\scripts\Build.ps1
```

Дополнительные проверки из PowerShell администратора, **до установки рабочей службы**:

```powershell
.\scripts\Test-Wfp.ps1
.\scripts\Test-Tun.ps1
```

WFP-тест затрагивает только отдельный тестовый EXE и удаляет свои блокировки в `finally`. TUN-тест использует синтетическую сеть `198.18.0.0/15` и отдельный интерфейс, не заменяет маршрут по умолчанию и не назначает системный DNS. Он выполняет реальные HTTPS-запросы к Cloudflare через PlanetVPN и напрямую. Журналы находятся в `artifacts`.

Обычный `Build.ps1` запускает проверки нормализации/приоритетов/запретов и `sing-box check` для конфигураций. Реальные сетевые проверки выделены отдельно, поскольку требуют сети и административных прав. Результаты текущей проверки — в [docs/VALIDATION.md](docs/VALIDATION.md).

## Остановка и удаление

Журналы: `%ProgramData%\SelectiveVpn\service.log`, `engine.log`, `openvpn.log`. На вкладке «Диагностика» есть кнопка «Открыть файл журнала». Для обычного отключения используйте кнопку в интерфейсе. При остановке службы защищённые приложения остаются заблокированными:

```powershell
Stop-Service SelectiveVpn
```

Удалить службу и **явно разрешить приложениям обычный интернет**:

```powershell
.\scripts\Uninstall.ps1 -RemoveApplicationBlocks
```

Без параметра `-RemoveApplicationBlocks` блокировки сохраняются. Скрипт оставляет бинарные файлы и зашифрованные настройки для восстановления. Аварийное снятие только собственных блокировок клиента:

```powershell
& "$env:ProgramFiles\SelectiveVpn\Service\SelectiveVpn.Service.exe" --remove-protection
```

## Время подключения, диагностика и вход в Windows

UI показывает длительность текущего подключения, время после последнего успешного переподключения, общее время в VPN, число подключений/повторных попыток/ошибок и последнюю причину сбоя. Счётчики относятся к текущему запуску службы; история предыдущих запусков остаётся в service.log. Они отражают жизненный цикл туннеля, а не успешность каждого запроса приложения.

«Подключать VPN при запуске службы» запускает VPN при старте службы, включая загрузку Windows до входа пользователя. «Подключать VPN при входе в Windows» отдельно отслеживает появление новой пользовательской сессии (до 2 секунд плюс ожидание текущей операции). Уже открытая сессия при старте службы не считается новым входом; разблокировка экрана не запускает VPN повторно. Настройка общая для компьютера. Для её работы служба должна быть запущена; при остановленной службе обработчик входа не работает. Сохраните изменения кнопкой «Сохранить изменения».

«Подробный журнал маршрутизации» включает debug в engine.log: поиск процесса, выбранные правила/outbound и причины закрытия соединений. Журнал ограничен 20 MB плюс предыдущая часть. Обычный режим — info. В окне диагностики и журнале службы прямые TCP-таймауты показываются сводкой раз в минуту. Отдельные записи остаются в engine.log. Ошибки VPN и критические ошибки движка появляются сразу. Журналы содержат адреса назначения и пути приложений.

Монитор проверяет VPN каждые 15 секунд. При потере соединения закрывает доступ защищённых приложений и назначает повторную попытку через 30 секунд; после неудачного полного подключения — через 60 секунд. Фактическое время зависит от проверки и таймера. Повторный тест проверяет восстановление после принудительного завершения только установленного sing-box.

## Системный трей

Крестик и Alt+F4 скрывают окно в трей, сохраняя несохранённый черновик. Двойной клик по значку или «Открыть» в меню возвращает окно. Опрос состояния продолжается, пока окно скрыто. Значок: зелёный — подключено, оранжевый — подключение/переход, красный — ошибка, серый — отключено/служба недоступна; подсказка уточняет состояние. Изменение отображается при следующем опросе (обычно до 3 секунд).

Меню содержит «Подключить», «Отключить», «Выход». Подключение использует выбранные настройки; при недоступной службе пытается её запустить. «Выход» завершает только UI и убирает значок, VPN-служба продолжает работать. При несохранённых изменениях запрашивается подтверждение выхода. Чтобы завершить и VPN, сначала выберите «Отключить», затем «Выход». Перед обновлением клиента завершайте интерфейс через «Выход», а не крестиком.

Регрессионные проверки трея: `dotnet run --project tests/SelectiveVpn.TrayTests -c Release`. Проверяют реальное скрытие/возврат WPF-окна, черновик, состояния значка, доступность команд и удаление значка при выходе. Команды подключения в проверке заменены локальными обработчиками; VPN не переключается.

## Добавление, проверка и удаление серверов

Вкладка «Серверы» содержит справку, кнопку «Обновить PlanetVPN» и импорт файла. Обновление загружает настройки бесплатных локаций из API. Оно сохраняет сторонние профили и старые записи для недоступных пулов. Импорт добавляет записи, а повторный импорт того же профиля с тем же именем и адресом обновляет его. Удалённый пул PlanetVPN скрыт при последующих обновлениях. Удаление активного сервера отключает VPN.

Поддерживаются Xray JSON с VLESS/REALITY по TCP или RAW, OpenVPN `.ovpn` с TCP/UDP по IPv4 и встроенными сертификатами, WireGuard `.conf` с одним `[Peer]` и явным `Endpoint`. Для OpenVPN с директивой `auth-user-pass` приложение запрашивает логин и пароль. Укажите `auth-user-pass` без ссылки на внешний файл. Скрипты из профилей запускать нельзя. Маршруты задаются в SelectiveVpn. Для выхода в интернет из WireGuard сети назначения должны входить в `AllowedIPs`.

«Проверить» измеряет время открытия порта TCP. Для OpenVPN UDP и WireGuard выводится результат ICMP ping до хоста. Ни одна из проверок не удостоверяет, что сервер примет ключ или пароль. Результат хранится до перезапуска службы или смены адреса профиля.

## Автозапуск интерфейса и перенос на другой компьютер

Галочка «При входе открывать интерфейс в трее» сохраняется сразу, отдельно от VPN-правил, для текущего пользователя. Создаётся задача планировщика `SelectiveVpn.UI.<SID>` с запуском установленного UI и аргументом `--tray`. Окно при запуске не показывается. Поскольку управление службой требует административных прав, задача регистрируется из повышенного UI и запускается с наивысшими правами в интерактивной сессии пользователя; пароль не хранится. Настройка не включает VPN: используйте независимые галочки подключения при запуске службы/входе пользователя. Отключение галочки удаляет задачу; Uninstall.ps1 удаляет задачи автозапуска интерфейса.

Предварительная установка PlanetVPN на целевом Windows x64 не нужна. Для переноса нужны `artifacts/publish` целиком (App, Service и Service/runtime с sing-box/OpenVPN/DLL/manifest), `scripts/Install.ps1` и локальный `private/provider-bootstrap.json` либо полный файл профилей для импорта. Устанавливать от администратора: `scripts/Install.ps1 -Provider private/provider-bootstrap.json`. Сохраните структуру каталогов проекта. Установленный .NET SDK или runtime не требуется: публикация self-contained. Файл настройки API не включён в Git; зашифрованные servers.dpapi/provider.dpapi с другого ПК переносить нельзя вместо исходного импорта — DPAPI привязан к компьютеру. Список серверов загружается через API; для автономного импорта можно передать `-Profiles` с исходными профилями.

Исходная установка PlanetVPN использовалась для получения совместимого OpenVPN и конфигураций. `Get-OpenVpn.ps1` обращается к ней только при сборке, если проверенных бинарных файлов ещё нет в runtime. Работа и установка готового полного комплекта от PlanetVPN не зависят. Установка на чистой Windows в отдельной VM пока не проверена; совместимость с произвольными брандмауэрами, драйверами и стандартными неадминистративными учётными записями не подтверждена.

## EXE на Inno Setup

Соберите установщик командой `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\Build-Inno.ps1`. На машине сборки нужен Inno Setup 6 или 7. При необходимости укажите `-Iscc` с путём к компилятору. EXE и файл SHA256 появятся в `artifacts/inno`.

Один EXE подходит для чистой установки и обновления, включая установку поверх копии из ZIP. Он переносит прежние файлы приложения в резервную папку на время обновления. Правила и профили остаются в ProgramData. Если VPN был активен, мастер проверяет его восстановление перед завершением.

## Полный установочный комплект

Сборка: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\Package.ps1`.
Скрипт собирает и проверяет клиент, включает оба движка, .NET, настройку из
`private/provider-bootstrap.json`, установщик и инструкцию. Результат — ZIP и
